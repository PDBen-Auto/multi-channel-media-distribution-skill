# 图像与视频：制作、返工和验收

## 制作前

读取源图/原视频内容，不从文件名猜功能。建立资产表：path、SHA256、bytes、来源、使用范围、实际尺寸/时长/声轨、render/sample/real-product等语义、可公开性。未知权利不伪造证明；用户直接授权用其提供素材制作时，不重复设泛泛的确认门槛，但新增音乐/人物/第三方图仍须核来源。

列清创意目标：受众为什么在首秒继续看、希望理解什么、主角是否清晰、哪些画面必须真实。输出尺寸/格式是本轮brief与实际渠道能力选择，不是永久1080p/18秒要求。

## 图片

按用户工具约束使用真实生成/编辑能力。至少检查产品几何、接口/支架、图案、颜色、文字和品牌；生成场景不能暗示未验证装车、性能或官方背书。多个主题需要不同信息任务，不能把同图另存三次。

最终文件存在且可解码、尺寸适合、缩略图与手机可读，ALT描述实际画面。明确标注AI/产品可视化，避免假照片或假实测。保持原件不变，记录来源和生成/编辑方法，不发布prompt中的私有内容。

## 视频制作

1. 拆解真实可用镜头、运动、声音、权利；不清楚音乐来源就剔除或用获准原创音效。
2. 设计首秒钩子、镜头节奏、连续运动、信息层次和CTA。强动效是剪辑/构图/图形/文字的表达，不是虚构产品功能。
3. 横竖版重新构图，不盲目居中裁切；保持产品主体、来源披露和字幕在实际安全区域。
4. 交付真实视频文件、封面、SRT/VTT、来源镜头表和声音来源。脚本、播放器HTML、关键帧不能代替MP4。

## 技术检查示例

```sh
ffprobe -v error -show_format -show_streams -of json final.mp4
ffmpeg -v error -i final.mp4 -f null -
ffmpeg -i final.mp4 -af volumedetect -vn -sn -dn -f null -
```

在有FFmpeg时检查真实编码、分辨率、时长、声轨、完整解码和声音幅度；记录命令、版本和输出。不固定误用特定峰值作所有项目合格线。无技术错误不等于好看，非零音频不等于有主观听感。

## 实际审片

| 检查 | 需要的证据 | 不能替代它的指标 |
|---|---|---|
| 完整播放 | 当前最终字节以正常速度播放至ended，检查起止、剪切、黑帧/冻结 | ffprobe元数据或一张截图 |
| 开场/节奏/运动 | 连续观看，说明主体运动、镜头变化、文字/图形如何传达目标 | 时长/帧数、转场数量 |
| 产品与来源 | 对照原图/样件、逐段来源，区别渲染与实拍，限制量产结论 | 文件名或AI自行描述 |
| 字幕与安全区 | 实际手机尺寸/横竖显示、裁切和可读时间 | 桌面全屏截帧 |
| 声音 | 权利、技术声轨检查，真实试听节奏/平衡；不能试听就unknown | 通过WebAudio或峰值测试 |
| 平台预览 | 实际编辑器中完整媒体、封面/裁切/字幕/音频与重编码 | 本地播放器通过 |

若只能使用代理页面加载真实字节作播放检查，注明是代理环境；不能把它说成file-origin或平台验证。自包含HTML应能直接打开，不为静态交付自动起服务器。

## 返工与版本

用户说“像幻灯片”，目标已超出编码正确：需要改镜头/运动/叙事方法。保留被退回版本，明确superseded；生成新版本和hash。按新标准重审，并检查所有渠道引用的时长、镜头、来源、文案与字幕；不把旧PASS继承给新字节。

审查者区分：技术检查通过、创意候选通过、用户采用、平台预览通过。某版好看不证明受众喜欢或产生转化。
